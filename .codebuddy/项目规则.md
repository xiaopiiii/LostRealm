# Lost Realm —— 项目规则

> 状态：对应 **beta30**。全文 7 节，读法如下：
> **§1 / §2 / §3 是红线**（违反 → 版本混乱、启动失败、一进世界就崩）；
> **§4 是静默失效速查**（不报错但功能没了，出问题先查这里）；
> §5 是数值契约，§6 是交付自检，§7 是协作方式。
>
> 改实体 / 渲染 / 模型前，先读 §3 与 §4 对应行；改数值前先读 §5。

---

## 1. 版本号：每次改动必做

**改任何行为 → `gradle.properties` 的 `mod_build` +1**（`beta30` → `beta31`）。
只改注释、不改行为时例外。

| 字段 | 值 | 职责 |
|---|---|---|
| `mod_version` | `1.0.0` | 主版本基底，**通常不动**，唯一作用是把版本串拼成数字开头 |
| `mod_build` | `beta30` | **唯一"活"的字段**，同时驱动 mods.toml 版本与 jar 文件名 |

`build.gradle` 是唯一的拼装点：`internalVersion = "${mod_version}-${mod_build}"`，
喂给 `version` 与 `archiveFileName`。`archiveFileName` **必须显式写**，
否则 Gradle 会产出 `...-1.0.0-beta29-1.0.0-beta29.jar` 这种双版本名。

> **为什么不能把 `beta29` 直接当 version**：Forge 校验正则是 `^\d+.*`
> （见 `ModInfo` 静态块 `VALID_VERSION`），字母开头会 `InvalidModFileException`，
> 表现为「不是有效的 Mod 文件」—— dv1~dv4 就这么全灭过。

配套动作：
1. `gradle.properties` 的版本历史注释块补一行（本版改了什么、为什么）；
2. 产物投放到 PCL 实例的 `mods/`（路径见 §6.1）；
3. 真实版本**以 `gradle.properties` 为准**，README 叙述可能滞后。

## 3. 崩溃红线（违反 = 起不来 / 一进世界就崩）

### 3.1 Mixin

- **全项目禁用 `@Shadow`**，字段访问一律 `@Accessor` / `@Invoker`。
  本项目的注解处理器**只**为 `@Accessor`/`@Invoker` 生成 refmap 字段映射；
  `@Shadow` 字段即使就在目标类里声明也不生成 → 正式环境 `InvalidMixinException`。
- 新增 Mixin 必须登记进 `lost_realm.mixins.json`（服务端进 `mixins`，客户端进 `client`）。
- 禁止 `@Inject` 缺稳定 SRG 名的 Forge 追加成员（如 `Level#addFreshEntity`）——
  refmap 不生条目，正式环境静默失效。选锚点前先用 `mcp_mappings.tsrg` 核对。

### 3.2 注册三件套（漏一个就崩/不可见）

| 注册了什么 | 必须同时有 | 漏了的表现 |
|---|---|---|
| `EntityType` | `EntityRenderer`（**MOD 总线** `FMLClientSetupEvent` + `enqueueWork`） | 客户端一进视野 NPE，崩在原版 `EntityRenderDispatcher`，`Suspected Mods: NONE` |
| `Block` | `blockstates/<name>.json` + 其**每个 variant** 对应的 `models/block/*.json` | 物品栏正常，放置后完全不可见 |
| `Item` | `models/item/<name>.json` + `layer0` 指向的贴图 | 不崩，游戏内紫黑格，日志一行 `Unable to load model` |

### 3.3 实体

- `defineSynchedData()` 分两种情形，**完全相反且都不报错**：
  - 父类是 `LivingEntity`/`Monster` → **必须** `super.defineSynchedData()`
    （漏了构造函数里 `setHealth` 直接 NPE，`/summon` 只报「无法召唤实体」，
    真因在日志 `Exception loading entity`）；
  - 直接继承 `Entity`/`Projectile`（抽象方法）→ **不能**调 super。
- 属性有硬上限（`MAX_HEALTH` 1024 等），超出被 `sanitizeValue()` 静默夹掉。
  本项目已由 `util/AttributeLimits` 抬到 1e6；新增高数值属性要确认上限。
- 体型缩放**只覆写 `getScale()`**，不要覆写 `getDimensions`（会平方缩放）；
  1.20.1 没有 `Attributes.SCALE`。改完记得 `refreshDimensions()`。
- 右键交互覆写 `Mob#mobInteract`（`protected`）；`interact` 是 `public final`，覆写即编译失败。

### 3.4 GeckoLib / 模型

- `GeckoLib.initialize()` 必须在 `@Mod` 构造器**第一行**；放 setup 事件里动画不播。
- 1.20.1 **Forge** 用 **4.4.x**；4.7+/4.8+ 面向 NeoForge，混用必崩。
- 动画文件顶层是 `{format_version, animations}`，**不能**再套一层文件名
  （geo 是 `{format_version, "minecraft:geometry": [...]}`，两者都被"多包一层"坑过）；
  套错 = 加载期 `Missing animations` 崩溃。
- 链式骨骼（触手/尾巴）：第 k 节 `pivot = 第 k-1 节末端`，**不是**自己中心；
  倾角存相对父节的增量；yaw 只加链首且两侧同号（靠挂载点 x 分左右）。
- 模型 x 轴必须以 0 为中心（`GeoEntityRenderer` 不做水平居中补偿），
  否则整体偏 0.5 格（"碰撞箱在中间、建模在旁边"）。
- 模型坐标 `-z` 是正面、`+z` 是背面；`z` 是深度不是高度。
- **直接继承 `EntityRenderer`（不是 `LivingEntityRenderer`）时，要自己补 `pose.scale(-1,-1,1)`**。
  原版 `LivingEntityRenderer#render` 里有一句翻转，`EntityRenderer` 没有；MC 模型空间 +Y 向下，
  漏掉这句整个模型上下颠倒。左右对称的体节看不出来，换成不对称的头（角 / 颚）立刻暴露。
- 贴图画布尺寸要按 **UV 展开后的最大需求**定：`box` 的 u 需到 `u + 2*(d+w)`，v 需到 `v + d + h`。
  超出的部分被 clamp 到最右列/最下行，表现是模型上出现一圈不该有的描边（本项目头部曾是 64×64 → 128×128）。
- 动画 `rotation` **替换**（不是叠加）几何里的静态 rotation，静态造型要烘进 cube 坐标。
- 一个 cube 的展开 UV 是 `2*(d+w) × (d+h)`；同类部件**共享**一块纹理区，
  不要逐 cube 独立 UV（装不下）。UV 常量只有 `tools/uv_layout.py` 一份。
- form2 资产由 `tools/bbmodel_to_gecko.py` 独占，`gen_geo.py`/`gen_anim.py`
  已剔除，**不要加回去**。要改只能重跑 bbmodel 管线。

### 3.5 世界生成

- **大批量搭结构用 `setBlock(pos, state, 2)`**（不触发邻居更新/光照重算）；
  清理先 `getBlockState(p).isAir()` 再写。半径 125 的地面是 4.9 万格，
  用 flag 3 会把首建从 1 秒拖到几十秒。
- 结构幂等哨兵**必须随布局改版换位置**，否则旧存档永远不重建
  （beta25 已换成「中心地下 4 格的哭泣的黑曜石」）。
- 虚空维度数据包最少 4 个文件，`default_block/fluid` 全 `minecraft:air`、
  `disable_mob_generation: true`、`continents: -1.0`。
- 1.20.1 没有 `Portal` 接口，跨维度走 `changeDimension(ServerLevel, ITeleporter)`。
- `BlockEntity` 的 `getTicker` 先 `if (level.isClientSide) return null;`，
  否则双端各推一次仪式/粒子。
- 自定义天空/雾走 `RegisterDimensionSpecialEffectsEvent`（MOD 总线）注册，
  `dimension_type/<id>.json` 的 `"effects"` 改成同一 ID；ID 对不上不会报错，
  只是回落到原版天空——**这类"没效果"优先查 ID 是否一致**。

### 3.6 属性与状态效果（beta30 起自注册）

- 12 条战斗属性 + `lost_realm:bleeding` 状态效果**由本模组自己注册**，
  不再依赖 Apothic Attributes（`attributeslib` / `placebo`）。
- **注册 ≠ 生效**。新增一条属性必须同时做完三件事，漏任一件就是「数值在、效果没」：

  | # | 动作 | 位置 |
  |---|---|---|
  | 1 | 注册并挂到实体 | `attribute/RealmAttributes`（`DeferredRegister` + `EntityAttributeModificationEvent`） |
  | 2 | **消费它**（让它真的改变结算） | `attribute/RealmAttributeEffects`，或专门的 Mixin |
  | 3 | 中英语言键 | `attribute.name.lost_realm.<id>` |

- 属性的**基础值与上下限是契约**，与 attributeslib 1.3.7 逐条对齐（见 §5.4）。
  改基础值 = 老存档的修饰符数值集体漂移，不要动。
- 新属性要挂到**所有**实体类型，不能只挂玩家：`getAttributeValue` 在属性缺失时返回 0，
  而 `healing_received / arrow_damage / draw_speed / experience_gained` 的
  「无加成」基准值是 **1.0** —— 缺属性会让治疗归零、箭伤清零。
- 护甲穿透只能走 `mixin/LivingEntityArmorPierceMixin`（注入 `getDamageAfterArmorAbsorb`）。
  事件层最早只能拿到「未扣护甲」的数值，`LivingHurtEvent` 里加伤害算不出破甲。
- 自建状态效果必须同时提供 `data/lost_realm/damage_type/<id>.json`，
  否则施加时抛「未知伤害类型」，报错指向注册表、极难联想。
- 持续伤害（流血等）的 `DamageSource` 要**留空直接实体**、只设造成者：
  `new DamageSource(holder, null, attacker)`。直接实体不为空时，
  吸血 / 元素附加 / 暴击会在**每一跳**上重复触发（挂个流血就永久回血）。

## 4. 静默失效速查（不报错，但功能没了）

> 用户报「看不见 / 没反应 / 没效果」时，**按本表顺序排查**，不要先怀疑材质、光照、网络。

| 症状 | 真因 | 修法 / 现状 |
|---|---|---|
| 只有头，身体不跟着 | 客户端位置从未同步（整合包里 `ClientboundMoveEntityPacket` 失效） | 服务端每 tick 下发脊线 `PacketErebosSpine`（40×3 float），客户端抄进 `segments`；**不要退回双端各自算** |
| 特定角度才看得见，一转头整条虫消失 | 剔除盒塌缩成一个点 | `getBoundingBoxForCulling()` 用**已同步**的 `spineNow` 算盒；取不到时退回 `体节盒 ∪ 本体盒` 再 `inflate(半身长)` |
| 召唤后一闪即消失 | 渲染器里重复减了一次摄像机 | `EntityRenderDispatcher.render()` 已 `pushPose + translate(x,y,z)`；渲染器**只能** `translate(体节 − 本体)`；插值用 `lerp(partialTick, xOld, getX())` |
| 换阶段"变大了"但模型不动 | `getScale()` 只影响碰撞箱，渲染管线不消费 | 渲染器 `preRender` 里 `poseStack.scale(...)` |
| 模型大但打不到 / 卡在方块里 | 客户端没刷尺寸 | 覆写 `onSyncedDataUpdated` 调 `refreshDimensions()` |
| 换阶段模型完全不动 | 动画引用了不存在的骨骼（静默跳过） | 生成脚本落盘前断言骨骼名存在于 geo |
| 满级 60 但终极技能永不触发 | 散落的 `level >= 30` 硬编码 | 判定一律读 `Skill#unlockLevel()` |
| 改了配置默认值，老存档没变 | Forge 配置生成后不再套新默认 | 写一次性迁移 + 标记（`_xxx_migrated_v1`），且**只在整组值都还是旧默认时才替换** |
| 勋章属性只有一项生效 | 整数 `pctDef` 吞小数 | 需要小数用 `pctDDef`，并配迁移 |
| 右键没反应 | 覆写了 `Mob#interact` | 改 `mobInteract` |
| 音乐完全没声音 | 初始 `volume=0` → `SoundEngine` 不建 source，后续推音量无效 | 初始 `0.01F`，`looping=true` |
| 模型上下颠倒（角朝下、牙朝上） | 继承 `EntityRenderer` 而没有 `scale(-1,-1,1)` | 见 §3.4；对称部件看不出来，别指望肉眼发现 |
| 模型边缘一圈灰蓝描边 | 贴图 UV 越界，越界处 clamp 到右边缘 | 扩大画布并重排 UV（同时改 `LayerDefinition.create(mesh, w, h)`） |
| 换了 `effects` 但天空没变 | 注册 ID 与 json 里的 ID 不一致 | 两处写成同一个 `ResourceLocation` |
| 移动一卡一卡 / 抽搐 / 瞬移后逐节跟上 | 单 tick 内硬位移过大，或脊线断点处理错 | 位移摊到多 tick；`ErebosTrail#length()` 遇断点即停 |
| 波次永远清不完 | 用「范围内所有 Monster」计数 | 用自定义 tag 过滤（`entity.getTags().contains(...)`） |
| 语言键对不上 | 只加了一边 | 中英双向差集都要为空，`%s` 数量一致 |
| **属性数值在、但完全没效果** | 只注册没消费（缺 `RealmAttributeEffects` 的分支） | 见 §3.6 三件套：注册 → 消费 → 语言键 |
| **挂上流血反而一直回血** | 持续伤害的 `DamageSource` 带了直接实体 | `BleedingEffect#source` 传 `null` 直接实体（§3.6） |
| **破甲毫无手感** | Mixin 未登记 / 护甲已被别的模组接管 | 查 `lost_realm.mixins.json` 有 `LivingEntityArmorPierceMixin`，refmap 里应有 `m_21161_` |
| **施加效果时抛「未知伤害类型」** | 只写了 Java，没写 `damage_type` json | 补 `data/lost_realm/damage_type/<id>.json` |

其他已固化的做法：
- **熟练度存勋章 NBT**（`data/MedalSource`），不存玩家；`PlayerMedals` 只留冷却/节点状态/时间戳。
  未佩戴时 `level()` 返回 1、`addExp` 静默丢弃，调用方不必判空。
  服务端直改勋章 NBT 后要 `MedalSourceSync.flush(player)`，否则 tooltip 不刷新。
- **章节枷锁存玩家 capability**（`PlayerMedals.shackleStage`），不存勋章 NBT
  —— 勋章会交易/掉落。破枷判定留纯函数入口 `MedalProgression#tryBreak`，命令与道具共用。
- **熟练度封顶只写在写入侧**（`MedalNbt#addExp`），不能在 `getLevel` 里 clamp
  —— 后者会让老存档掉级。封顶取 `totalExpForLevel(cap+1) - 1`。
- **配置值不可写成 `static final`**：走访问器方法（如 `BossRegistry#bossMaxHealth()`），
  内部对 `ConfigValue == null` 兜底。启动早期事件早于配置加载。
- **可选前置一律走 `compat/` 桥接 + try-catch 降级**，不新建第二套桥接。
- 百分比配置一律**整数**（`20` = 20%），代码里 `MedalsConfig.pct()` 除以 100。
- `AttributeModifier` 一律用 `util/ModifierIds` 的固定 UUID，防止叠加。

## 5. 数值契约（改之前先看这里）

### 5.1 熟练度 / 勋章

| 项 | 值 |
|---|---|
| 等级上限 | 60（`MedalsConfig.MAX_LEVEL`，旧存档 30→60 自动迁移） |
| 技能节点 | 每 10 级一个 |
| 章节枷锁 | 20 级 / 40 级，各需一个破枷印记（`MedalShackleItem`） |
| 成长曲线 | 每 10 级一档：**7 / 6 / 5 / 4 / 3 / 2 %** |
| 档位算法 | `ExpTable` 按 `(level-1)/10` 取档（**不是** `level/10`，否则 10→11 提前跳档） |
| 累计经验 | Lv.20 ≈ 3,643；Lv.40 ≈ 14,478；Lv.60 ≈ 36,168 |

三章节奏（按此校验击杀量）：第一章 ≈121 次、第二章 ≈483、第三章 ≈1,206。

### 5.2 遗落之主（Erebos）

`boss/erebos/ErebosTuning.java` 是**唯一**调参入口：

| 项 | 值 |
|---|---|
| 环节 | 50 节 × 4.2 格 = 全长 210 格；体径 4.8；碰撞部件 5.2 |
| 血量 | 12,000（配合 `AttributeLimits`） |
| 巡游 | 1.25 格/tick，半径 32~58，到达阈值 12 |
| 冲锋 / 星门 | 4.5 / 5.0 格/tick |
| 登场 | 1.1 格/tick（min 0.85），超时 400 tick 硬切 |
| 阶段血线 | 80% / 60% / 15% |
| 巡游节拍 | 50 / 40 / 25 / 0 tick（阶段Ⅳ 不停） |
| 弹幕 | 单轮上限 72，场上上限 360 |

登场轨迹是**盘绕**（半径 = 总弧长 / 2π），不是直线铺开；星门是「头部先穿、身体逐节跟进」，
结束条件看 `isFullyEmerged`，不要按 tick 数判。

演出相关的固定值（beta29）：

| 项 | 值 | 位置 |
|---|---|---|
| 死亡碎块 | 每节 7 块、头部 10 块，共 **360 块**；波锋扫过用 `shattered[]` 去重，否则翻四倍 | `ErebosBoss#spawnShards` |
| BGM 切分 | 全曲 179.7s，切在 **84.0s**（实测 RMS 最低点）；Ⅰ/Ⅱ 前段，Ⅲ/Ⅳ 后段 | `ModSounds` + `ErebosMusicController` |
| 天空强度 | 阶段Ⅰ 0.25 → Ⅳ 1.0，`0.25 + index*0.25` | `ErebosSkyEffects#setIntensity` |

### 5.3 竞技场

250 格地板、外圈柱半径 100、12 根柱、柱顶挂根之图腾、外墙半径 123×高 30；
中央单祭坛右键启动 **20 秒**仪式（`LostAltarBlock` + `BossRegistry.RITUAL_TICKS`），
同时保留直接用召唤物召唤的路径。

### 5.4 战斗属性（beta30 起自注册，单位不可改）

注册处：`attribute/RealmAttributes`；消费处：`attribute/RealmAttributeEffects` + 破甲 Mixin。

| 属性 ID | 基础 | 下限 | 上限 | 语义 | 谁在消费 |
|---|---|---|---|---|---|
| `crit_chance` | 0.05 | 0 | 10 | 暴击概率，1.0 = 100% | `onHurtCrit`（**仅物理**） |
| `crit_damage` | 1.5 | 1 | 100 | 暴击倍率 | `onHurtCrit` / `onVanillaCrit` |
| `life_steal` | 0 | 0 | 10 | 吸血比例，0.1 = 10% | `onHurtPost` |
| `armor_pierce` | 0 | 0 | 1000 | 固定护甲穿透（点） | `LivingEntityArmorPierceMixin` |
| `dodge_chance` | 0 | 0 | 1 | 闪避概率 | `onAttackDodge` / `onProjectileDodge` |
| `overheal` | 0 | 0 | 10 | 溢出治疗转吸收，上限 50% 最大生命 | `onHurtPost` |
| `healing_received` | 1.0 | 0 | 1000 | 受疗倍率 | `onHeal` |
| `experience_gained` | 1.0 | 0 | 1000 | 经验倍率，11.0 = +1000% | `onXpDrop` |
| `fire_damage` | 0 | 0 | 1000 | 近战附带火焰伤害（点） | `onHurtPost` |
| `cold_damage` | 0 | 0 | 1000 | 近战附带冰霜伤害（点） | `onHurtPost` |
| `arrow_damage` | 1.0 | 0 | 10 | 箭矢基础伤害倍率 | `onArrowJoin` |
| `draw_speed` | 1.0 | 0 | 4 | 拉弓速度倍率 | `onUseItemTick` |

**两条与 attributeslib 的原版实现有意不同（改动前先想清楚，别当 bug 修回去）**：

1. **暴击限定物理伤害**。attributeslib 对任意 `LivingHurtEvent` 都掷骰，
   于是法师的魔法伤害会同时吃战士的 `crit_chance` 和法师自己的
   `spell_crit_chance`，双重暴击。现在 `onHurtCrit` 用 `isPhysical()` 过滤。
2. **火焰 / 冰霜附加伤害并入本次结算**。attributeslib 会另起一次 `hurt()`
   （自带自定义伤害类型，绕过无敌帧与护甲）；本模组不新增那两个伤害类型，
   改为直接在 `LivingHurtEvent` 里加算，因此**会吃护甲**。
   量级只有个位数，观感是「刀上带的元素附魔」。

**已知的历史包袱**：拆掉 attributeslib 后，护甲公式回到原版
（`clamp(护甲 - 伤害/(2+韧性/4), 护甲×0.2, 20)/25`）。
attributeslib 装着的时期它把护甲换成了 `a/(a+护甲)` 的公式，
所以**同样的护甲值，现在挨的伤害会比 beta29 略高**。这是移除前置的必然结果，
不是调参失误；要找回旧手感只能整体下调护甲数值。

## 7. 协作方式

- **不把第三方模组 jar 放进仓库或交付包**（属二次分发，违反 CurseForge/Modrinth 条款）。
  `libs/` 只保留 `README.md` 说明清单与下载地址；`build.gradle` 在配置阶段检查文件是否存在，
  缺失时抛带版本号与链接的中文错误。玩家侧的前置由启动器/整合包自行安装。
- **每次改完就自动构建并投放，不用等用户喊**（2026-11-01 用户指定，取代原先的"不主动构建"）。
  顺序：改代码 → `mod_build` 递增 → `./gradlew clean build --offline` → 跑 §6 自检 → 投放 jar → 推 GitHub。
  构建失败就地修，不许把编译不过的代码留在工作区里。
  投放路径见 §6 第 10 项。
- 不臆测 API：拿不准就 `javap -p -c` 反编译原版或依赖 jar 验证，再看字节码下结论。
- 可实测的就实测：`/tmp/lrtest` 起生产服务端 + RCON（端口 25575，密码 `lr`），
  比推断可靠。离线几何/数值问题先写脚本模拟。
- 排查顺序固定：**剔除盒 → 渲染器是否被调用 → 坐标基准 → 同步数据**，
  而不是先怀疑贴图、透明、光照。
- 交付时说清：改了哪些文件、为什么、怎么验证、还剩什么没做。

### 7.1 每次改动都要推 GitHub（2026-11-01 起）

**触发条件**：任何一次「完成」的改动 —— 加功能、修 bug、调数值、改文档都算。

#### 本机 git 的两个坑（换机器/重装后必看）

1. **TLS**：这台机器走透明代理，`schannel` 后端必然报
   `CRYPT_E_NO_REVOCATION_CHECK (0x80092012)`，而 `-c http.schannelCheckRevoke=false`
   在这个 Git 版本上不生效。已改为 **OpenSSL 后端 + 系统根证书**，写在仓库本地 config：
   ```
   http.sslBackend = openssl
   http.sslCAInfo  = C:/Users/22310/.workbuddy/git-win-ca.pem
   ```
   证书包是 `Cert:\LocalMachine\Root` + `Cert:\CurrentUser\Root` 导出的 PEM（78 张）。
   换机器要重新导一次；不要用 `GIT_SSL_NO_VERIFY=1` 绕过，那等于关掉校验。
2. **认证**：PAT **不写进任何文件**，每次推送临时用
   `-c http.extraheader="AUTHORIZATION: Basic <base64(x-access-token:PAT)>"`。
   因此**每次推送都需要用户当次提供 PAT**，不要假装还能推。
   如果需要免手输，让用户自己配 `git credential-manager`，不要代为保存明文 token。
